##### Gas优化

在第一次优化过程基本参考辉哥分享的清单，下面对清单未提到的部分进行描述

1. 在内存中缓存读取变量

   从存储成本中的变量读取`gas`。当我们第一次访问一个变量时，它会花费`2100 gas`并且后续访问将花费`100 gas`。如果我们有一个数组并想对数组元素执行一些计算。`length`读取数组并将其存储在变量中可能更有效。如果数组不是太大，我们也可以将整个数组读`array`入内存并从内存中访问它，而不是不断地从存储中读取。

   ```solidity
   RLPReader.RLPItem[] memory txInfoItem = decodeItem[index].toList();
   uint256 itemLength = txInfoItem.length;
   bytes[] memory txInfo = new bytes[](itemLength);
   for (uint256 txInfoIndex = 0; txInfoIndex < itemLength; ) 
   {
   	txInfo[txInfoIndex] = txInfoItem[txInfoIndex].toBytes();
   	uncheck{
   	++txInfoIndex;
   	}
   }
   params.txInfo = txInfo;
   ```

   由于SPV合约中对数组的遍历是较为多的，所以此部分节省Gas的效果是比较明显的

2. 使用 revert 而不是 require

   `require`用来检查语句是否为`true`. 如果声明评估为假，交易将被还原，剩余的气体将返回给用户。但如果需要自定义错误内容的话，我们可以使用该`revert`语句来抛出自定义错误。

   ```solidity
   error NotEmptyRootHash();
   error NotEqualNodeValue();
   error InvalidRootHash(bytes32 wantRootHash, bytes32 getRootHash);
   error InvalidTxHash(bytes32 wantTxHash, bytes32 getTxHash);
   error InvalidTxInfo();
   error InvalidBlockHash(bytes32 wantBlockHash, bytes32 getBlockHash);
   error InvalidMPTProofs();
   error InvalidProofOfInclusion();
   error L1InputNotContainL2Tx();
   error MaxTrackBlockNumber();
   ```

   经过实践，节省Gas的效果是比较明显的

3. 尽量使用solidity内置方法

   在写SPV合约时，使用的版本为0.8.4，此时的版本不支持bytes到 bytesNN值的转换，因此使用了第三方库或者使用汇编实现；在与MDC、EBC合约合并时，升级到0.8.17版本，翻阅了每一版的更新点，发现了在0.8.5之后，官方已经开始支持此类型转换。

4. 前面说的尽量使用内置方法基本是通用的，但如果有涉及到复杂的逻辑，可使用汇编。如只需进行一次Keccak256，使用内置方法就行；双重Keccak256可采用汇编。例如MPT证明中使用到双重Keccak256
5. 乘法和除法可以使用位移进行代替。MUL 和 DIV 操作码消耗 5 gas，而 SHL 和 SHR 仅消耗 3 gas。
6. 使用较小的uint打包在一个插槽。如uint8 uint64

##### 安全方面

1. 利用经过安全审计的受信任合约库和接口 如OpenZeppelin、solidity-bytes-utils
2. 保持合约逻辑简单，对合约进行模块化，保持合约和功能较小 如从SPV中分离出Decode部分
