# AI Space 六大图片工具优化方案 v2

> 综合考量：模型能力 vs 本地脚本、精度需求、实现成本、用户体验。
> 替代 v1 方案（`docs/plans/2026-06-16-image-editing-tools-optimization.md`）。

---

## 一、核心策略

### 1. 分类驱动，不是全丢给模型

| 分类 | 原则 | 工具 | 主要技术 |
|---|---|---|---|
| **像素保真型** | 尺寸不变、构图不变、主体不重绘 | 背景移除、文字移除、保真画质提升 | 本地脚本为主 |
| **生成修改型** | 允许在选区内生成新内容 | 局部重绘、区域涂抹 | gpt-image-1 + mask |
| **混合型** | 生成 + 本地合成 | 背景替换 | image2 生背景 + 本地合成 |

### 2. 每个工具都要解决的三个问题

1. **可控**：用户能看到/选择处理范围，不是盲处理
2. **精确**：只改该改的地方，不该改的不动
3. **可反馈**：处理完能看到效果好不好，不好能修正

### 3. 模型使用决策

| 模型 | 角色 | 用在哪 |
|---|---|---|
| gpt-image-2（image2） | 文生图 | 背景替换中的"纯背景层生成" |
| gpt-image-1 | 图像编辑 + mask | 局部重绘、区域涂抹、文字移除兜底 |
| 本地脚本 | 像素级操作 | 背景移除、文字检测、保真增强、超分、合成 |

不把保真型操作交给生成模型——因为生成模型一定会改变非目标区域。

## 二、六大工具优化方案

---

### 1. 背景移除

#### 当前问题
- 只有一种 rembg u2net 模型，不分图片类型
- 边缘处理粗糙：毛发、透明物体、商品硬边效果不稳定
- 用户无法微调结果

#### 优化方案

**模型路由（本地）**：

| 图片类型 | 抠图策略 |
|---|---|
| 人像 | rembg + 边缘 feather |
| 毛发/动物 | rembg + alpha matting 精修 |
| 商品硬边 | rembg + 硬边优化（去白边/黑边） |
| 动漫 | rembg 或 SAM 分割 |

**前端增加模式选择**：
- 标准（默认，当前行为）
- 精细毛发
- 商品硬边
- 去白边/去黑边

**前端增加结果微调**（P1）：
- 修边笔刷：恢复主体 / 擦除残边 / 边缘羽化
- 预览背景切换：透明棋盘格 / 白底 / 黑底

**后端改动**：
- `remove_background.py` 增加 `--mode` 参数，按模式选不同后处理
- 输出严格 PNG/RGBA，尺寸等于输入

**不接 gpt-image-1** 的理由：rembg 像素级分割比生成模型更准、更快、零 API 费。生成模型做透明 alpha 边缘容易出伪影。

---

### 2. 背景替换

#### 当前问题
- 已有 image2 生背景 + 本地 alpha 合成链路 ✅
- 但无光照匹配、无接触阴影、边缘有白边/黑边
- 主体和背景"不像在同一个场景"

#### 优化方案

**保留现有链路，加后处理融合**：

```
image2 生成纯背景 → 本地抠主体 alpha → alpha 合成 → 光照/阴影/边缘融合
```

**融合层增强**（`replace_background.py`）：

1. **色调匹配**：取主体平均色温/亮度，对背景做轻微色调调整
2. **接触阴影**：主体底部自动添加 soft shadow（高斯模糊 + alpha 渐变）
3. **边缘 light-wrap**：主体边缘吸收一点背景环境光色，消除白边
4. 可通过参数开关：`--shadow none|soft|strong`、`--color-match on|off`、`--light-wrap on|off`

**前端增加参数**：
- 光照方向（左/右/顶/自动）
- 接触阴影（无/自然/强）
- 主体保护（严格/允许边缘融合）

**前端增加背景模板**：
- 纯色 / 渐变 / 电商白底 / 摄影棚 / 办公室 / 家居 / 城市街景 / 沙滩 / 国风 / 电影感

**不改变**：image2 生成背景 + 本地合成的分工不变。只加合成后的融合步骤。

---

### 3. 文字移除 ← 核心优化

#### 当前问题
- 只有 OpenCV 形态学检测，没有真实 OCR
- 没有预览，用户不知道系统会删哪里
- 不能选择"只删某段文字"
- 截图图标容易被误删

#### 优化方案：三阶段精确文字移除

**阶段一：检测 + 预览**

```
上传图片 → PaddleOCR 检测文字 → 返回文字框坐标 + 文字内容 → 前端显示检测预览
```

- 新建 `detect_text_mask.py`：用 PaddleOCR 检测文字区域，返回 JSON：
  ```json
  {
    "regions": [
      {"bbox": [x1,y1,x2,y2], "text": "促销", "confidence": 0.95},
      {"bbox": [x1,y1,x2,y2], "text": "¥99", "confidence": 0.91}
    ]
  }
  ```
- 后端新增 preview API：`POST /api/images/edit/preview`，返回文字框列表
- 前端在图片上叠加红色框 + 文字内容标签

**阶段二：用户选择**

- 默认全选"删除所有检测到的文字"
- 用户可以：
  - 点击单个文字框取消（"这个不删"）
  - 框选/涂抹补充漏检文字
  - 擦除误检区域（如图标被误判为文字）
- 图标保护：检测时过滤高饱和度方形区域、UI 元素特征

**阶段三：精确执行**

- 按用户选定的文字框生成精确 mask
- mask 扩张（2-5px）+ 轻微羽化
- 按背景类型选修复方式：

  | 背景类型 | 修复策略 |
  |---|---|
  | 纯色/渐变 | OpenCV inpaint（本地，快，像素保真） |
  | 简单纹理 | OpenCV inpaint + texture continuity |
  | 复杂背景 | gpt-image-1 mask inpaint（生成式补图） |
  | 海报大标题 | gpt-image-1 mask inpaint |

- 修复后二次 OCR 检查：如果仍读到目标文字，扩大 mask 再来一次

**模式选择**：
- 自动删除全部（默认）
- 手动选择删除
- 只删水印/字幕

**保留**：现有 `remove_text.py` 的形态学检测作为 fallback（PaddleOCR 装不上时）。

### 4. 画质提升

#### 当前问题
- 只有保真增强（denoise + CLAHE + sharpen），没有 AI 超分
- 前端 UI 已拆分 faithful/ai，但后端无论选哪个都走同一脚本

#### 优化方案

**拆成三条路径**：

| 模式 | 技术 | 尺寸 | 用途 |
|---|---|---|---|
| 保真增强 | OpenCV denoise + CLAHE + sharpen | 原尺寸 | 截图、商品图、"不要变样" |
| AI 超分 2x | Real-ESRGAN | 2x 放大 | 模糊照片、老照片 |
| AI 超分 4x | Real-ESRGAN + GFPGAN | 4x 放大 | 人脸修复 + 高清 |

**后端改动**：
- `enhance_quality.py` 保留保真增强路径
- 新建 `upscale_ai.py`：封装 Real-ESRGAN，支持 `--scale 2|4`、`--face-enhance on|off`
- `processQualityEnhancementJob` 按 `route.SubMode` 分流到不同脚本

**前端模式**：
- 保真增强（默认）
- AI 高清 2x
- AI 高清 4x
- 人脸修复（4x + GFPGAN）
- 动漫高清（anime upscaler，P1）

**不接生成模型** 的理由：Real-ESRGAN 是确定性超分，不会改变内容、不会重绘人脸，比 gpt-image-1 更可控。

### 5. 局部重绘

#### 当前问题
- 已走 gpt-image-1 + mask ✅
- 但不区分编辑意图，mask 扩张策略统一
- 不显示识别对象名，用户不知道系统理解了什么

#### 优化方案

**增加意图区分 + mask 策略**：

| 子模式 | mask 策略 | 说明 |
|---|---|---|
| 替换物体 | 轮廓 + 扩张 5-10px + feather | "把杯子换花瓶"，mask 要比物体略大 |
| 修改属性 | 轮廓 + 小 feather | "衣服改红色"，mask 贴合物体 |
| 新增内容 | 用户涂抹区域，不扩张 | "桌上加咖啡"，mask 就是放置区 |
| 修复瑕疵 | 原始涂抹 + 小扩张 | "修掉划痕"，最小干预 |

**`refine_mask.py` 增加 `--intent` 参数**：
- 按意图选不同扩张幅度和羽化半径
- 返回 mask 覆盖率给前端显示

**前端增强**：
- 涂抹后显示"已识别：[对象名]"（用 gpt-image-1 vision 或本地 SAM）
- 显示 mask 覆盖率
- 支持手动调整 mask 边界（扩大/收缩/清除）

**保留**：gpt-image-1 为主力的编辑链路不变。

---

### 6. 区域涂抹

#### 当前问题
- 已走 gpt-image-1 + mask ✅
- 不自动包含阴影/反射
- 无残影检测，有时删不干净

#### 优化方案

**增加阴影自动包含**：

| 子模式 | mask 处理 | 说明 |
|---|---|---|
| 标准删除 | 用户涂抹区域 | 只删选中物体 |
| 包含阴影 | 涂抹区域 + 底部/周围扩张检测阴影 | 阴影一起删 |
| 强力清除 | 扩张 mask + 二次修复 | 删不干净再扩大来一次 |

**`refine_mask.py` 对 region-brush 的处理**：
- `include-shadow`：在涂抹区域下方/周围检测阴影（亮度 < 阈值 + 连通区域），自动并入 mask
- `strong-cleanup`：mask 扩张 15-20px

**残影二次检测**：
- 第一次生成后，取 mask 边缘区域对比原图
- 如果仍有原物体颜色/轮廓残留 → 扩大 mask → 再调一次 gpt-image-1
- 最多重试一次

**固化删除 prompt**：
```
Remove the selected object completely. Fill the area naturally using the
surrounding background. Do not add new objects. Preserve all unmasked areas exactly.
```

**前端增加**：
- 删除强度选择（标准/包含阴影/强力清除）
- 结果上显示"检测到残留 → 自动修复中"的反馈

## 三、共享能力

### 1. 统一 mask 系统

局部重绘、区域涂抹、文字移除共享同一套 mask 编辑器：
- 画笔 / 橡皮 / 智能识别
- 扩张 / 收缩 / 羽化 / 清除
- 处理区域预览（红色=将修改，绿色=将保护）

### 2. 统一 preview API

```
POST /api/images/edit/preview
  → { edit_mode, image_url, sub_mode }
  ← { regions: [...], mask_preview: "data:..." }
```

文字移除返回文字框 + OCR 内容；局部重绘返回识别对象名 + mask；区域涂抹返回检测物体 + 建议阴影区域。

### 3. 统一质检

每次编辑完成后记录：
- 输出尺寸 == 输入尺寸？（保真型）
- 非 mask 区域是否变化？（生成型）
- 文字是否仍可读到？（文字移除）
- mask 覆盖率是否合理？

## 五、技术栈

| 层 | 技术 | 用途 |
|---|---|---|
| 文字检测 | PaddleOCR | 文字框坐标 + 内容识别 |
| 精确分割 | rembg / SAM | 背景移除、主体抠图 |
| 超分 | Real-ESRGAN | AI 高清 2x/4x |
| 人脸修复 | GFPGAN / CodeFormer | 人脸增强 |
| 本地修复 | OpenCV inpaint / LaMa | 文字移除（简单背景） |
| 生成编辑 | gpt-image-1 + mask | 局部重绘、区域涂抹、复杂文字移除兜底 |
| 背景生成 | gpt-image-2 (image2) | 背景替换的纯背景层 |
| 合成融合 | OpenCV / PIL | alpha 合成、光照匹配、阴影 |

## 六、最终目标

用户看到的还是六个工具，但每个工具背后：

- 背景移除：按图选模型 → 边缘精修 → 可手动补抠
- 背景替换：生背景 → 抠主体 → 合成 → 光照融合
- 文字移除：OCR 检测 → **用户选哪些删** → 精确 mask → 分类型修复 → 残影检查
- 画质提升：保真增强 / AI 超分 / 人脸修复，三条独立路径
- 局部重绘：涂抹 → 识别对象 → intent 分化 mask → gpt-image-1 编辑
- 区域涂抹：涂抹 → 自动含阴影 → 删除 → 残影检测 → 必要时再来一次
