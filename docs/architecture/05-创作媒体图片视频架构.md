# 创作媒体图片视频架构

## 一、定位

创作媒体架构覆盖图片生成、图片编辑、图片会话、视频生成、视频会话和本地媒体资产服务。目标是让远端生成结果变成平台内可管理、可预览、可复用的资产。

## 二、模块图

```mermaid
flowchart TD
  FE[Creative 前端页面] --> IMGAPI[/api/images*]
  FE --> IMGC[/api/image-chats*]
  FE --> VIDAPI[/api/videos*]
  FE --> VIDC[/api/video-chats*]

  IMGAPI --> ImageHandler
  ImageHandler --> ImageService
  ImageService --> ImageProvider[Image Gen Provider]
  ImageHandler --> DB[(Image records)]
  ImageHandler --> IFS[(本地 images assets)]

  VIDAPI --> VideoHandler
  VideoHandler --> VideoService
  VideoService --> Volc[Volcengine Seedance]
  VideoHandler --> VFS[(本地 videos assets)]
  VideoHandler --> DB
```

## 三、图片生成/编辑

图片接口支持：

- 文生图：prompt、aspect ratio、resolution、quality。
- 图像编辑：remove-bg、replace-bg、text-removal、upscale 等模式。
- 多参考图：`reference_image_urls`。
- 本地访问：生成后保存为 `/api/images/file/:filename`。

图片尺寸在后端统一规范化，保证满足模型要求，例如边长对齐到 16 的倍数。

## 四、视频生成

视频生成链路：

1. 前端提交 prompt、model、ratio、resolution、duration、audio/watermark、参考图/视频。
2. 后端校验并规范化参数。
3. `VideoService` 创建远端任务。
4. 保存 `VideoGeneration` 记录。
5. 前端查询/刷新状态。
6. 成功后后端拉取远端视频，保存本地资产，返回 `/api/videos/file/:filename`。

## 五、参考素材解析

视频参考素材可以是外部 URL，也可以是平台内部文件。内部文件通过 `resolveVideoReferenceURLs` 转为可被远端服务访问的 URL；本地开发环境必要时可回退为 data URL。

## 六、媒体资产本地化原则

| 原则 | 说明 |
|---|---|
| 远端结果不直接依赖 | 生成成功后要落本地，避免远端 URL 过期 |
| 前端统一访问相对路径 | 图片 `/api/images/file/*`，视频 `/api/videos/file/*` |
| 删除记录时清理本地资产 | 避免磁盘无限增长 |
| 历史面板只读记录表 | 不从文件目录反扫资产 |

## 七、前端体验重点

- 生成中卡片需要稳定高度和 skeleton。
- 历史面板需要懒加载缩略图，避免一次性加载大图/视频。
- 视频状态刷新要明确：排队、生成中、保存中、失败、完成。
- 参考素材上传和复用要统一，不要图片页、视频页各自一套不兼容状态。

## 八、风险点

| 风险 | 影响 | 建议 |
|---|---|---|
| 远端视频成功但本地保存失败 | 用户看到失败/丢资产 | 单独展示“保存失败”，保留 task 信息 |
| 大视频下载阻塞请求 | API 超时 | 后续改后台本地化任务 |
| 历史面板图片太多 | 页面卡顿 | 懒加载、分页、缩略图 |
| 参考文件不可公网访问 | 远端生成失败 | BASE_URL/FRONTEND_URL 配置检查 |
