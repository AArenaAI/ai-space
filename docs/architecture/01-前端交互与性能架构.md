# 前端交互与性能架构

## 一、定位

前端是 AI Pool 用户体验的第一瓶颈层。当前前端使用 Next.js App Router + React Client Components，功能集中在聊天、创作、工作区、技能、设置、登录注册等页面。优化重点应放在减少卡顿、闪烁、阻塞和无意义重渲染，而不是继续堆入口。

## 二、页面分区

| 区域 | 路径 | 说明 |
|---|---|---|
| 聊天壳 | `app/(chat-shell)/chat/page.tsx` | 主聊天页，承载会话、对比、收藏、分享 |
| 技能聊天 | `app/skills`, `app/skills/chat` | 技能列表与技能专属聊天 |
| 创作 | `app/(main)/(creative)` | 图片、视频、模板、图片/视频会话 |
| 工作 | `app/(main)/(work)` | 文档研读、翻译、写作助手 |
| 应用 | `app/(main)/(app)` | PPT、workspace、settings |
| 账户/营销 | `login/register/pricing/page.tsx` | 登录注册、定价、落地页 |

## 四、状态管理边界

| 状态 | 当前承载 | 注意点 |
|---|---|---|
| 消息列表 | `useChat` React state | 需要控制高频流式更新造成的整体重渲染 |
| 流式临时内容 | `lib/streaming` Map store | 适合高频 append，避免每 token 都触发全树刷新 |
| 实时状态 | `realtimeUpdate/realtimeGet` | 用于活动状态、搜索、任务元信息 |
| 选中模型 | localStorage + React state | 技能推荐模型不要在生成中强切 |
| 对比模式 | localStorage + React state | 对比状态需要和历史会话状态区分 |
| 用户身份 | localStorage token/user + AuthInterceptor | 401 时统一拦截，避免页面散落处理 |

## 五、卡顿来源

1. **Markdown/ECharts/代码块渲染重**：长消息持续增长时，如果整条消息每个 chunk 重渲染，会出现输入区和滚动卡顿。
2. **聊天页状态过大**：`useChat` 同时管理历史、流式、对比、后台任务、分页、技能模型，容易引发连锁 render。
3. **侧边栏/历史列表刷新闪烁**：会话重命名、创建、删除通过 window event 刷新，若全量拉取会造成视觉跳动。
4. **媒体历史图片/视频加载重**：创作页历史面板若未做懒加载/尺寸稳定，滚动时容易抖。
5. **文件上传状态不清晰**：解析、embedding、视觉兜底状态如果只在后端存在，前端会表现成等待无反馈。

## 六、优化原则

- 聊天正文和输入区隔离：输入区不要因为消息流式增长而重新布局。
- 长消息渲染分层：流式文本、完成后的 Markdown 渲染、图表渲染分阶段处理。
- 历史列表局部更新：创建/重命名/删除不要导致整个侧栏闪烁。
- skeleton 优先于空白：文件、媒体、PPT、历史列表都要有稳定占位。
- 弹窗/抽屉统一：删除、分享、命名、输入类交互复用 `components/ui`。

## 七、建议的前端性能改造顺序

| 优先级 | 改造 | 验收 |
|---|---|---|
| P0 | 聊天流式渲染降频/分层 | 长回答时输入框不卡、滚动不跳 |
| P0 | MessageList 虚拟化或窗口化 | 大历史会话打开不明显卡顿 |
| P0 | Markdown 完成后再重渲染重组件 | 流式阶段不反复渲染 ECharts/复杂代码块 |
| P1 | 侧栏历史局部 patch | 新建/重命名/删除无全屏闪烁 |
| P1 | 媒体历史懒加载和固定尺寸 | 图片/视频列表滚动稳定 |
| P1 | 文件状态统一组件 | 上传、解析、可用、失败状态清晰 |

## 八、实现注意

- UI 样式继续使用 Tailwind theme tokens，避免硬编码颜色。
- Full-width 工作台页面不要加 `mx-auto max-w-7xl`，内容应吃满视口。
- 布局容器必须明确 `flex-col`，避免 `flex` 默认 row 导致内容被挤到一侧。
- 非流式 UI 问题不要擅自改流式核心代码；聊天页修复要范围隔离。
