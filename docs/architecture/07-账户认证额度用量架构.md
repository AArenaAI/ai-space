# 账户认证额度用量架构

## 一、定位

账户、额度和用量架构是商业化基础。它同时服务匿名用户试用、登录用户持久化、模型成本控制、套餐展示和接口限流。

## 二、认证层

```mermaid
flowchart LR
  FE[前端 token/localStorage] --> API[/api]
  API --> Optional[OptionalAuthMiddleware]
  API --> Auth[AuthMiddleware]
  Optional --> Guest[匿名 guest_id]
  Optional --> User[登录 user_id]
  Auth --> User
```

路由分三类：

| 类型 | 示例 | 说明 |
|---|---|---|
| 公开 | `/health`, `/api/models`, `/api/auth/login` | 不需要身份 |
| 可选认证 | `/api/chat`, `/api/files/upload` | 支持匿名和登录用户 |
| 强认证 | `/api/conversations`, `/api/images`, `/api/videos`, `/api/ppt` | 必须登录 |

## 三、额度与套餐

后端配置包含：

- 匿名每日聊天次数/金额限制。
- 各 Provider 输入/输出价格。
- 图片、视频按张/次计费。
- 模型 tier 与公开 plans。

前端通过 `CreditBar`、定价页和设置页展示用户额度。

## 四、用量记录

`UsageService` 负责记录 API 调用成本，核心数据进入 `api_usage_logs`。它应记录：

- user/guest
- service/provider/model
- input/output/total tokens
- 单价和总成本
- request/task/message 关联
- success/failure 状态

## 五、限流

`RateLimitMiddleware` 提供 IP 维度保护，并对高频读取端点做豁免，例如图片文件访问、收藏检查、会话列表等。

设计目标：

- 防止匿名用户刷接口。
- 不让历史列表/图片加载这类高频读被误伤。
- 为未来用户级、模型级、Provider 级限流留边界。

## 六、商业化扩展方向

| 能力 | 当前基础 | 后续建议 |
|---|---|---|
| 匿名试用 | guest id + daily limit | 增加设备/IP/成本综合风控 |
| 套餐 | plans endpoint | 接入支付和订阅状态 |
| 成本 | APIUsageLog | 后台成本报表和异常预警 |
| 模型 tier | `/api/models/tiers` | 前端明确展示成本/速度/能力标签 |

## 七、风险点

| 风险 | 影响 | 建议 |
|---|---|---|
| 前端只展示次数不展示成本 | 用户不理解额度消耗 | 模型选择器显示价格/档位 |
| 匿名限制只按次数 | 高成本模型可被滥用 | 优先按金额限制 |
| 用量记录和任务状态脱节 | 成本统计不准 | 任务完成/失败时统一落 usage |
