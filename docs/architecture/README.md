# AI Pool 架构文档索引

本目录是 AI Pool 当前有效的架构文档集合。结构采用「总架构 + 分架构」：总架构描述系统边界、模块关系和核心链路；每个分架构只展开总架构中的一个架构点，避免旧文档分散、重复、互相冲突。

## 文档结构

| 文档 | 说明 |
|---|---|
| `00-AI-Pool总架构.md` | 全局系统架构、模块地图、主数据流、关键设计原则 |
| `01-前端交互与性能架构.md` | Next.js/React 前端、页面分层、状态管理、卡顿治理方向 |
| `02-聊天消息与流式生成架构.md` | 聊天请求、消息持久化、任务事件、SSE 流式与恢复 |
| `03-模型Provider与SSE解码架构.md` | 多 Provider 适配、统一请求、流式解码、后台任务模型 |
| `04-文件上传解析与RAG架构.md` | 上传、解析、Direct-First、历史文件 RAG、Embedding 降级 |
| `05-创作媒体图片视频架构.md` | 图片生成/编辑、视频生成、媒体资产本地化与历史记录 |
| `06-PPT文档生成架构.md` | PPT 生成、提纲确认、页面改写、配图、导出链路 |
| `07-账户认证额度用量架构.md` | 用户认证、匿名用户、额度、价格、用量日志 |
| `08-数据存储与任务事件架构.md` | SQLite/GORM、核心表、WAL、后台任务事件表 |
| `09-部署运行与网关架构.md` | 前后端部署、同源 API 代理、端口、运行约束 |

## 维护规则

1. 新增架构点时，先在总架构中补入口，再单独新增分架构文档。
2. 分架构只描述一个主题，避免把聊天、文件、媒体、PPT 混写在同一份文档里。
3. 过期架构文档不要继续放在 `docs/` 根目录；被本目录替代的旧文档应删除或归档。
4. 文档应以当前代码为准，不以早期产品策划案为准。
