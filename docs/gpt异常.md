单用户额度限制；\n- 异常调用检测。\n\n这类功能比“聊天界面”更适合 B2B 付费。\n\n### 产品三：Model Evaluation Platform\n\n帮企业比较：\n\n- 哪个模型写代码好；\n- 哪个模型中文好；\n- 哪个模型客服好；\n- 哪个模型幻觉少；\n- 哪个模型最便宜；\n- 哪个模型在特定任务上综合最优。\n\n平台可以让客户上传自己的测试集，然后自动跑多模型 benchmark。\n\n### 产品四：Agent Observability\n\n海外 AI Agent 公司会需要：\n\n- trace；\n- prompt 版本管理；\n- 工具调用日志；\n- RAG 命中率；\n- 失败原因分析；\n- hallucination 检测；\n- jailbreak 检测；\n- 用户反馈回流。\n\n这会是比“模型聚合”更深的护城河。\n\n---\n\n## 3. 海外合规重点\n\n### 1）欧盟：GDPR + AI Act\n\n如果面向欧盟用户，GDPR 很重要。欧盟官方说明指出，GDPR 不仅适用于欧盟组织，也适用于向欧盟境内个人提供商品或服务、或监测其行为的非欧盟组织；数据跨境传输时也需要相应保障。([europa.eu](https://europa.eu/youreurope/business/dealing-with-customers/data-protection/data-protection-gdpr/index_en.htm))\n\n同时，欧盟 AI Act 已进入分阶段实施期：通用条款和禁止性规则自 2025年2月起适用，通用目的 AI 规则自 2025年8月起适用，大部分规则和高风险 AI 系统相关规则自 2026年8月起适用。([ai-act-service-desk.ec.europa.eu](https://ai-act-service-desk.ec.europa.eu/en/ai-act/eu-ai-act-implementation-timeline))\n\n因此海外版要提前准备：\n\n- DPA 数据处理协议；\n- SCC 标准合同条款；\n- EU data residency；\n- 数据删除机制；\n- 用户数据不用于训练的承诺；\n- 高风险场景限制；\n- 模型来源与用途说明；\n- AI 输出标识和免责声明。\n\n### 2）美国：隐私、消费者保护和行业合规\n\n美国没有单一全国性 AI 法，但有 FTC、州隐私法、行业规则等。NIST AI RMF 是美国重要的自愿性 AI 风险管理框架，NIST 还在 2024年发布了生成式 AI 风险管理相关 Profile，供组织识别和管理生成式 AI 风险。([nist.gov](https://www.nist.gov/itl/ai-risk-management-framework))\n\n如果要做海外企业客户，建议尽早准备：\n\n- SOC 2 Type II；\n- ISO 27001；\n- 数据加密；\n- 审计日志；\n- SSO/SAML；\n- RBAC 权限；\n- Zero Data Retention 选项；\n- 私有云/VPC 部署；\n- 安全白皮书。\n\n---\n\n# 五、国内与海外应该采用“双轨架构”\n\n我建议不要用一个平台同时服务国内外，而是采用：\n\n\u003e **双实体、双品牌、双数据中心、共享技术底座、隔离客户数据。**\n\n## 推荐架构\n\n| 项目 | 中国内地版 | 海外版 |\n|---|---|---|\n| 法人主体 | 中国内地公司 | 香港/新加坡/美国公司 |\n| 域名品牌 | 独立国内域名 | 独立国际域名 |\n| 云服务 | 阿里云/腾讯云/华为云中国区 | AWS/GCP/Azure/Cloudflare |\n| 模型接入 | 已备案国产模型 + 私有化开源模型 | OpenAI、Anthropic、Gemini、Mistral、Llama 等 |\n| 数据存储 | 中国境内存储 | 按地区分 US/EU/SEA |\n| 支付 | 微信、支付宝、对公转账、发票 | Stripe、PayPal、信用卡 |\n| 合规重点 | 备案、内容安全、数据安全 | GDPR、AI Act、SOC 2、隐私协议 |\n| 客户重点 | 企业、政企、制造、电商、客服 | 开发者、AI 初创、SaaS、全球企业 |\n\n核心原则：\n\n\u003e **代码可以复用，数据不要混；能力可以共享，合规要分开。**\n\n---\n\n# 六、最推荐的切入顺序\n\n## 第一步：先做模型网关\n\n先实现：\n\n- 多模型统一 API；\n- 统一计费；\n- 模型路由；\n- fallback；\n- 日志；\n- 成本看板；\n- 企业权限。\n\n这是底座。\n\n## 第二步：做企业知识库/RAG\n\n这是最容易成交的企业应用。\n\n国内卖：\n\n- 企业内部知识库；\n- 智能客服；\n- 文档问答；\n- 合同/制度问答。\n\n海外卖：\n\n- 开发者文档问答；\n- SaaS 客服机器人；\n- technical support agent；\n- internal copilot。\n\n## 第三步：做模型评测和成本优化\n\n这是差异化。\n\n客户会愿意为这些问题付费：\n\n- 哪个模型最适合我？\n- 怎么降低 30% token 成本？\n- 怎么保证模型挂了业务不中断？\n- 怎么知道员工有没有乱用 AI？\n- 怎么防止敏感数据被发给外部模型？\n\n## 第四步：做工作流和 Agent 平台\n\n最后再进入：\n\n- Agent builder；\n- workflow marketplace；\n- 插件市场；\n- 行业模板；\n- 企业流程自动化。\n\n不要一开始就做大而全，容易失焦。\n\n---\n\n# 七、重点风险\n\n## 1. 纯 API 转售利润薄\n\n如果只是“买模型 API 再卖给用户”，毛利会越来越薄。平台必须靠：\n\n- 路由；\n- 缓存；\n- 工作流；\n- 企业权限；\n- 合规审计；\n- 私有化部署；\n- 行业模板；\n\n来提高附加值。\n\n## 2. 国内公开 C 端合规压力大\n\n公开 C 端聊天产品在中国内地要面对内容安全、备案、投诉、未成年人保护、生成内容标识等问题，不适合资源有限的创业公司作为第一战场。\n\n## 3. 海外竞争激烈\n\n海外已经有多个成熟 AI Gateway 和模型聚合平台，单纯“我支持更多模型”不是护城河。真正的差异化应放在：\n\n- 更好的路由策略；\n- 更低延迟；\n- 更透明计费；\n- 更好的企业治理；\n- 更强的模型评测；\n- 更好的亚洲市场服务。\n\n## 4. 数据安全事故会毁掉平台\n\nAI 聚合平台天然\n\n下面我按**“一个新的 AI 聚合平台”**来分析：它不是单纯做 ChatGPT 套壳，而是做 **多模型接入、智能路由、工作流/RAG、企业治理、计费与安全合规**的一体化平台。\n\n## 一、先给结论\n\n**中国内地：优先做 B2B/企业级，不建议一开始做公开 C 端“海外模型聚合站”。**  \n核心卖点是：**合规、安全、私有化部署、国产模型聚合、企业知识库和业务流程落地**。\n\n**海外：优先做开发者/API 平台和 SaaS，走 PLG 增长。**  \n核心卖点是：**一个 API Key 调用多家模型、自动路由、降本、低延迟、故障切换、可观测性和模型评测**。\n\n一句话：\n\n\u003e **国内卖“合规 + 落地 + 私有化”，海外卖“效率 + 成本 + 开发者体验”。**\n\n---\n\n# 二、AI 聚合平台应该做成什么形态？\n\n一个有竞争力的 AI 聚合平台，最好不是只做“聊天入口”，而是做成下面这几层：\n\n## 1. 模型聚合层\n\n接入多家大模型：\n\n- 国内：通义、文心、豆包、智谱、Kimi、DeepSeek 等合规模型；\n- 海外：OpenAI、Anthropic、Google Gemini、Mistral、Meta Llama 等；\n- 开源：Qwen、Llama、Mistral、DeepSeek 系列等可私有化部署模型。\n\n海外已有类似方向的平台，例如 Vercel AI Gateway 提供统一 API 访问多模型，并支持预算、使用监控、负载均衡和故障切换；LiteLLM 也提供用 OpenAI 格式调用 100+ LLM、统一输出、重试/回退、成本跟踪等能力。([vercel.com](https://vercel.com/docs/ai-gateway/))\n\n## 2. 智能路由层\n\n平台要能判断：\n\n- 简单任务用便宜模型；\n- 复杂任务用高性能模型；\n- 中文任务优先国内强模型；\n- 代码任务优先代码能力强的模型；\n- 当某个模型宕机或限流时自动切换；\n- 根据客户要求决定是否允许数据出境。\n\n这才是平台真正的技术价值。\n\n## 3. 企业应用层\n\n包括：\n\n- 企业知识库问答；\n- 文档总结；\n- 客服机器人；\n- 代码助手；\n- 营销内容生成；\n- 招投标文档辅助；\n- 合同审阅；\n- 内部制度问答；\n- Agent 工作流；\n- RAG 检索增强。\n\n## 4. 治理与安全层\n\n企业客户真正关心的是：\n\n- 数据是否泄露；\n- 模型回答是否可控；\n- 谁调用了什么模型；\n- 花了多少钱；\n- 是否可以审计；\n- 是否符合内部合规要求；\n- 能否私有化部署。\n\n所以 AI 聚合平台的护城河不只是“接模型多”，而是**模型治理能力**。\n\n---\n\n# 三、中国内地如何开展业务？\n\n## 1. 市场定位：不要先做“万能 AI 聊天站”，要先做企业平台\n\n在中国内地，公开面向公众提供生成式 AI 服务，需要面对备案、内容安全、算法治理、数据安全等多重要求。《生成式人工智能服务管理暂行办法》明确适用于利用生成式 AI 技术向中国境内公众提供文本、图片、音频、视频等内容的服务，并且官方解读中也将“通过 API 等方式提供生成式人工智能服务”的组织、个人纳入服务提供者范围。([gov.cn](https://www.gov.cn/zhengce/zhengceku/202307/content_6891752.htm?utm_source=openai))\n\n因此，最稳妥的切入方式是：\n\n\u003e **B2B 企业内部使用 + 私有化/专有云部署 + 已备案模型接入 + 内容安全网关。**\n\n不要一开始做这种模式：\n\n\u003e “给中国内地用户提供一个入口，转发调用海外 ChatGPT/Claude/Gemini。”\n\n这类模式在支付、数据出境、内容合规、模型备案、服务稳定性上都有明显风险。\n\n---\n\n## 2. 合规路径：内地必须先把底座搭稳\n\n内地业务至少要考虑以下几类合规事项：\n\n### 1）ICP备案 / APP备案 / 经营许可判断\n\n如果在中国境内提供网站、APP 或 SaaS 服务，通常要处理 ICP/APP 备案问题；工信部办事指南明确，未取得许可或未履行备案手续，不得从事互联网信息服务。([ythzxfw.miit.gov.cn](https://ythzxfw.miit.gov.cn/bssx/alx/dxhhlw/art/2025/art_88c400fc83904008bcf5b11bc08ec18f.html))\n\n如果涉及经营性互联网信息服务，还要进一步判断是否需要增值电信业务经营许可证。\n\n### 2）生成式 AI 服务备案与登记\n\n如果平台面向公众提供生成式 AI 能力，要关注生成式 AI 服务备案。国家网信办已建立生成式 AI 服务备案与登记机制；对于通过 API 接口或其他方式直接调用已备案模型能力的生成式 AI 应用或功能，地方网信办会开展登记。([gov.cn](https://www.gov.cn/lianbo/bumen/202404/content_6943924.htm?utm_source=openai))\n\n### 3）算法备案\n\n如果平台具有舆论属性或社会动员能力，可能触发算法备案要求。《互联网信息服务算法推荐管理规定》要求相关算法推荐服务提供者在提供服务之日起十个工作日内履行备案手续。([gov.cn](https://www.gov.cn/zhengce/2022-01/04/content_5728941.htm?utm_source=openai))\n\n### 4）AI 生成内容标识\n\n《人工智能生成合成内容标识办法》自 2025年9月1日起施行，要求规范 AI 生成合成内容标识；这意味着平台如果提供文本、图片、音频、视频生成能力，需要设计显式/隐式标识、元数据标识、传播链路识别等能力。([gov.cn](https://www.gov.cn/lianbo/bumen/202503/content_7014283.htm?utm_source=openai))\n\n### 5）数据出境与个人信息保护\n\n如果国内用户数据要传到海外模型或海外服务器，需要处理数据出境问题。《促进和规范数据跨境流动规定》对个人信息出境的免评估、标准合同、个人信息保护认证、安全评估等场景进行了规定，例如非关键信息基础设施运营者当年累计向境外提供 10万人以上、不满100万人个人信息，或不满1万人敏感个人信息的，应订立个人信息出境标准合同或通过个人信息保护认证。([gov.cn](https://www.gov.cn/gongbao/2024/issue_11366/202405/content_6954192.html?utm_source=openai))\n\n---\n\n## 3. 国内产品策略：做“企业 AI 中台”\n\n我建议国内版本主打四个产品：\n\n### 产品一：国产大模型统一网关\n\n功能包括：\n\n- 一个 API 调用多个国内模型；\n- 模型统一鉴权；\n- 统一计费；\n- 统一日志；\n- 统一内容安全；\n- 自动模型切换；\n- 成本监控；\n- 企业级权限管理。\n\n目标客户：\n\n- SaaS 公司；\n- 电商公司；\n- 内容平台；\n- 教育科技公司；\n- 智能客服公司；\n- 企业数字化部门。\n\n### 产品二：企业知识库 + RAG 平台\n\n这是国内最容易落地的方向。\n\n企业有大量内部资料：\n\n- 产品手册；\n- 售后文档；\n- 合同模板；\n- 规章制度；\n- 培训资料；\n- 招投标文件；\n- 研发文档；\n- 客服记录。\n\n平台可以帮助企业把这些资料变成可问答的 AI 助手。\n\n### 产品三：低代码 Agent 工作流\n\n做成类似：\n\n- 上传文件；\n- 选择模型；\n- 配置知识库；\n- 拖拽流程；\n- 接入飞书、钉钉、企业微信；\n- 最后生成一个内部 AI 应用。\n\n这比单纯卖 API 更容易让企业买单。\n\n### 产品四：AI 合规安全网关\n\n这是国内很有价值的差异化方向：\n\n- 输入内容检测；\n- 输出内容检测；\n- 敏感信息脱敏；\n- 政策风险过滤；\n- 个人信息识别；\n- 审计日志；\n- AI 生成内容标识；\n- 模型调用留痕；\n- 企业权限分级。\n\n这个产品可以卖给已经在用大模型的企业，帮它们补安全和合规短板。\n\n---\n\n## 4. 国内商业模式\n\n建议采用 **“SaaS + 私有化 + 服务费”** 混合模式。\n\n| 客户类型 | 推荐模式 | 收费方式 |\n|---|---|---|\n| 中小企业 | 公有云 SaaS | 账号费 + token 用量费 |\n| 中大型企业 | 专有云部署 | 年费 + 实施费 + 运维费 |\n| 政企/金融/制造 | 私有化部署 | 项目制 + license + 定制开发 |\n| 开发者 | API 网关 | 充值/按量计费 |\n| SaaS 厂商 | 模型转售/网关 | 分成 + 用量阶梯价 |\n\n国内最容易赚钱的不是 C 端会员，而是：\n\n\u003e **企业知识库、内部助手、AI 客服、文档自动化、私有化部署、模型治理。**\n\n---\n\n# 四、海外如何开展业务？\n\n## 1. 海外定位：开发者优先，企业跟进\n\n海外市场已经有 OpenRouter、Poe、Vercel AI Gateway、LiteLLM 等玩家。OpenRouter 文档显示其 Models API 会返回标准化 JSON，并提供模型元数据；Vercel AI Gateway 也强调一个 API Key 访问多模型、统一 API、自动重试、支出监控等能力。([openrouter.ai](https://openrouter.ai/docs/guides/overview/models))\n\n所以海外市场不能只说“我也能聚合很多模型”，这已经不够了。\n\n你要打的差异点应该是：\n\n- 更便宜；\n- 更快；\n- 更稳定；\n- 更适合亚洲/跨境团队；\n- 更好的模型评测；\n- 更好的企业权限；\n-
