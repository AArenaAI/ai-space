# AI 聚合平台项目策划案

## 一、项目定位

**名称**：待定（建议简洁易记，如 ChatHub / AIHub / 智聚合）
**Slogan**：一个入口，所有顶尖 AI
**目标用户**：国内个人用户、学生、职场人士、中小企业
**核心痛点**：
- 国内用户无法直接访问 GPT、Claude 等海外 AI
- 多个 AI 平台来回切换，体验割裂
- 海外 AI 付费门槛高（需要外币信用卡、容易被封号）
- 中文场景下各模型表现参差不齐，需要一个"智能路由"自动选择最佳模型

## 二、竞品分析（ToxAI 拆解）

| 维度 | ToxAI 现状 | 我们的机会点 |
|------|-----------|------------|
| **技术栈** | Next.js + React，现代化前端 | 可借鉴，但我们可以加入更多本土优化 |
| **模型覆盖** | Claude、GPT、Gemini 聊天 + gpt-image-2 画图 + PPT | 可以扩展更多国产模型（DeepSeek、Kimi、通义千问、文心一言） |
| **功能模块** | 聊天 / 画图 / PPT / 联网搜索 | 可以增加：文档解析、语音对话、代码解释器、Agent 市场 |
| **UI 设计** | 左侧导航栏 + 中间会话列表 + 右侧聊天区，简洁现代 | 参考其布局，但增加更多自定义皮肤和主题 |
| **用户体系** | 必须登录才能保存对话历史 | 可以提供游客模式（限量体验），降低使用门槛 |
| **商业模式** | 推测为会员订阅制（按量/包月） | 可以采用"免费额度 + 会员订阅 + API 接口"三级模式 |

## 三、核心功能模块

当前代码边界已经比较清晰，产品层建议固定为四条主路径：**Chat / Compare / Search / Image**。

### 3.1 Chat（当前主路径）
Chat 负责所有文本类能力，统一入口：聊天输入框 → `POST /api/chat`。

包含：
- **单模型聊天**：普通问答、代码生成、总结、翻译等
- **流式输出**：SSE 实时返回
- **Reasoning 深度思考**：作为 Chat 参数控制，不是独立产品
- **文件问答**：上传文档后做检索增强并注入上下文
- **图片理解**：上传图片后做多模态分析
- **图表生成**：输出 `echarts` 代码块，由前端渲染真实图表

边界说明：
- “画折线图 / 柱状图 / 饼图 / 趋势图” 属于 Chat，不属于 Image
- Chat 默认应禁用模型的泛工具自动调用，避免把图表需求误路由成图片生成导致空输出

### 3.2 Compare（当前已落地）
Compare 是 Chat 的多模型对比形态，统一入口：`POST /api/chat/compare`。

包含：
- **多模型并行回答**：同一问题发给多个模型并列展示
- **非流式一次性返回**：便于对比结果统一保存
- **结果持久化**：对比结果可保存为普通消息
- **Reasoning / Search / 文件上下文**：与 Chat 共用主要能力边界

产品价值：
- 方便用户比较 GPT、Claude、DeepSeek、Kimi 等模型在同一问题上的差异
- 对文件问答、搜索问答、复杂推理场景尤其有价值

### 3.3 Search（当前已落地，作为增强开关）
Search 不是独立会话入口，而是 Chat / Compare 的增强层。

触发规则：
- 只由前端“搜索开关”控制
- 不由自然语言里的“帮我查一下”自动触发

建议固定规则：
- **支持原生搜索能力的模型**：优先使用模型内置 `web_search`
- **不支持原生搜索能力的模型**：由平台先做第三方搜索，再把结果注入 prompt

第三方搜索链路：
1. Tavily
2. Tavily 失败后降级 Brave
3. Brave fallback 抓部分网页正文片段

边界说明：
- Search 是产品增强能力，不是单独模型类别
- Compare 与 Chat 应保持同一套搜索预处理规则，避免不同模式行为不一致

### 3.4 Image（当前已落地）
Image 是独立图片生成入口，不应由 Chat 自动推断触发。

统一入口：`POST /api/images/generate`

包含：
- **文生图**
- **参考图编辑 / 图生图**
- **异步任务处理**
- **图片记录列表 / 状态查询 / 文件访问**

当前实现边界：
- 图片模型固定为 `gpt-image-2`
- 文生图走 `/v1/images/generations`
- 参考图编辑走 `/v1/images/edits`
- 生成过程异步化，前端轮询任务状态

### 3.5 规划扩展能力
在四条主路径稳定后，可以继续扩展：
- **PPT 生成**：已落地，可继续增强模板、导出和版式能力
- **文档处理增强**：更强的 RAG、OCR、长文档解析
- **代码助手**：围绕 Chat 提供更好的代码问答与重构体验
- **Agent 市场**：作为更高阶能力层，而不是替代 Chat 主路径
- **语音交互**：未来可作为 Chat 的输入/输出增强层

## 五、商业模式

### 5.1 免费用户
- 每日 20 次基础模型对话额度
- 无法使用高级模型（GPT-4o / Claude 3.5）
- 无法保存历史记录（或仅保存最近 3 条）

### 5.2 会员订阅（主力收入）
| 档位 | 价格（参考） | 权益 |
|------|------------|------|
| 基础版 | ¥29/月 | 每日 100 次，可用 GPT-4o-mini / DeepSeek |
| 专业版 | ¥69/月 | 每日 500 次，可用 GPT-4o / Claude 3.5 / Gemini，支持文件上传 |
| 高级版 | ¥169/月 | 无限次（合理范围内），全模型 + 画图 + PPT + 优先响应 |

### 5.3 API 接口（B 端收入）
- 向开发者提供统一 API，按 Token 计费
- 价格比官方低 10-20%，但比我们自己采购成本高 30-50%（赚差价）

### 5.4 企业定制
- 私有化部署
- 企业内部知识库 + AI 问答
- 定制 Agent

## 六、差异化竞争策略

1. **比 ToxAI 更多模型**：不仅做海外模型，还要接入国内最好的模型（DeepSeek、Kimi），让用户在同一个地方比较海内外 AI 的差异
2. **中文场景优化**：
   - 预设大量中文 Prompt 模板（小红书文案、抖音脚本、公文写作、论文降重）
   - 针对中文长文本优化（Kimi 的 200 万字上下文是巨大卖点）
3. **本地化体验**：
   - 微信支付 / 支付宝订阅
   - 国内服务器部署，访问速度快
   - 客服用中文
4. **价格优势**：通过批量采购 API + 国产模型补充，把成本压下来，会员价比用户自己买 ChatGPT Plus + Claude Pro 便宜

## 八、风险与应对

| 风险 | 应对策略 |
|------|---------|
| 海外 API 被封/限流 | 多账号池轮换 + 国产模型作为兜底 |
| 政策合规 | 接入内容安全审核（阿里云/百度内容审核 API），过滤敏感词 |
| 成本失控 | 设置用户级限流 + 模型降级策略（高峰期用便宜模型） |
| 同质化竞争 | 聚焦"中文场景 + 国内模型 + 价格优势"，不做大而全 |

---

## 九、总结

这个项目市场空间很大——国内想用上 GPT/Claude 但没有条件的人太多了。ToxAI 已经验证了模式可行，但功能还可以做得更丰富、更本土化。

**核心公式**：海外顶尖模型 + 国产优质模型 + 中文场景优化 + 低价会员 = 一个有竞争力的 AI 聚合平台。
